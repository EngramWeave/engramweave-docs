# Discard is a reversible lifecycle mark, not a processing stage

Source, Draft, and formal knowledge file Properties store `lifecycle_status: active | discarded`, with rebuildable Core projections. Discard preserves the previous processing stage. Source discard may mark related Drafts; all referencing formal knowledge is listed for explicit user selection. ChangeSets are temporary execution plans outside this lifecycle. Successful integration only auto-discards related Drafts.

User file operations confirm explicit target lists; AI proposals use ChangeSet. Physical deletion is separate cleanup after marking. Referenced active Sources are skipped by default; users can override after the reference warning, leaving broken links untouched. Deleting a Source Record also removes its associated derived data and its dedicated Capture-owned Asset under `20_Sources`. External shared Assets are not managed or deleted. Restoration defaults to Source only with optional related-object selection; historical integrated Drafts are not automatically reactivated.
