# Integration is one knowledge-reorganization capability

Integration Planner decides how reviewed content should reorganize the current library and produces one candidate ChangeSet, including creation, modification, splitting, merging, restructuring, or discard as needed. These are descriptions of outcomes, not separate product modes or four independent workflows.

The first useful release preserves the full reorganization scope through one inspection, editing, rejection, replanning, and approval mechanism, rather than reducing integration to selected business-operation modes. Deterministic execution may use concrete file primitives, but those primitives do not define the user's planning choices; physical deletion still follows the separate discard-and-cleanup contract.
